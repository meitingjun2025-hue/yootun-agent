# yootun 插件 UI/UX 统一规范（2026-11-15）

本文是 [1110/05-ui-ux.md](1110/05-ui-ux.md) 的插件阶段扩展，对后续迁入 `yootun/plugins/` 的全部业务插件用户界面具有强制约束力。品牌前端、激活门禁与设置区块仍以分册 05 为准；插件页面在遵守该册的基础上，还必须遵守本文的页面结构、组件、数据图表与插件助手规范。

本文的交互与形态思想来自对两个官方推荐社区插件的只读勘察（2026-11-15，`dsh-media-desk` 2.7.1、`dsh-context` 0.84.1）：`dsh-media-desk` 的产品化工作台、右侧助手 Dock、上下文引用与可撤销操作回执；`dsh-context` 的洞察优先仪表盘、交互式图表、筛选联动与形状匹配加载态。两家仓库的功能、业务内容、代码、素材、截图和文案不迁移；不复制其 `md-*` / `lc-*` 私有组件、Tailwind 用法、字面色值或业务资产。它们的空间节奏、任务组织、图表语言和复合交互可以在 yootun 的受控创作层重译。

## 一、设计原则

| 原则 | 含义 | 来源与转化 |
|---|---|---|
| 插件即工作台 | 业务插件不是设置表单堆叠，而是能完成一个任务域的中央面板：有清晰导航、状态、筛选、内容区和可选助手 | 吸收 media-desk 的产品化工作台思路；页面仍注册在官方 `main` / `sidebar.panellist` 体系内 |
| 洞察优先 | 数据页面先回答业务问题，再展示原始数据；KPI、趋势、构成和明细逐层展开 | 吸收 context 的仪表盘信息架构；图表全部用官方 token 重做 |
| 图表即筛选器 | 悬停解释数据，点击或键盘选择后反查明细；筛选条件以 chip 显示并可一键清除 | 吸收 context 的联动查询体验；交互必须可键盘操作 |
| 助手在任务现场 | 助手常驻插件页面侧边，可直接使用已配置模型处理当前对象，不需要切回主会话 | 吸收 media-desk 的助手 Dock；模型调用必须走 Host 与企业凭证链 |
| 操作可解释、可恢复 | AI 修改数据时逐条显示回执，失败保留原数据，最近一次有效修改可撤销 | 吸收 media-desk 的 receipts / undo 语义 |
| 状态永远真实 | 加载、空态、降级、无权限、失败分别呈现；不用空白、假数据或假成功掩盖 | 两者的骨架与错误处理均作为交互参考 |
| 官方底盘 + 受控创作 | 主题 token、原子控件、文案与无障碍底盘遵循官方；官方没有的复合形态由 yootun 自建，允许业务界面保有个性 | 社区插件提供 UX 与形态参考，不提供可复制实现 |

### 1.1 三层创作模型

yootun 不把“符合官方规范”理解为只能拼官方既有组件。官方体系约束材料、控件语义、可达性与主题；官方没有的能力必须自创，否则插件会退成表单堆叠。自创按三层治理：

| 层 | 组件归属 | 强制规则 | 允许的自创 |
|---|---|---|---|
| 官方底盘 | DSH slots / layout / theme / `ui-primitives` | 挂载、token、原子控件、焦点、浮层、文案、动效遵守官方 | 不改官方主题、不重做 Button/Input/Menu/Modal 等原子件 |
| yootun 复合层 | `@yootun/dsh-client-ui-kit`（首批插件时建立） | 内部仍复用官方原子件与 token；一套组件服务全部插件 | `PluginPageShell`、`AssistantDock`、`DataCard`、`KpiCard`、`ChartFrame`、图表族、`FilterBar`、`DataState`、`OperationReceipts` |
| 插件场景层 | 各业务插件局部 CSS Modules / 组件 | 不重做通用原子件；状态、键盘、主题、响应式完整；第二个消费者出现时上移 | 领域画布、看板、日历、媒体墙、时间轴、拓扑图、专属空态与任务动线 |

自创准入判断按顺序执行：

1. 查官方 primitive 与 slot：已有原子能力必须复用，即使局部重画看起来更轻；
2. 区分原子与复合：按钮、输入、菜单、开关、弹窗、提示是原子；图表、Dock、工作台、看板、时间轴是复合；
3. 官方没有且跨插件可复用时，进入 yootun kit，不落在单个插件；
4. 只服务一个业务域时先留在插件局部，并在该插件的验收文档中说明为什么暂不共享；
5. 同一形态出现第二个消费者时必须抽取；不允许第三个插件再复制；
6. 自创视觉必须有明暗主题、loading / empty / error / disabled / focus / hover / pressed、窄容器与 reduced-motion 状态。

场景层的风格弹性白名单：

- 任务氛围：局部 hero、淡品牌渐变、细网格、数据纹理；不得覆盖整页或与内容争夺注意力；
- 领域画布：自由布局、卡片墙、看板、泳道、关系线，但必须提供键盘可达的等价列表或详情；
- 数据色彩：集中定义 `--yt-chart-*` 语义类别色，优先映射 `--dsw-static-*`；不得散落字面色值；
- 领域插画：只用于空态、引导或不可替代的业务对象，不用作装饰堆叠；
- 微动效：服务于空间关系、生成进度、筛选联动或数据变化，不添加无语义循环动画。

| 上下文引用 | 把当前对象或选区变成可见 chip，随问题一起提交，用户可移除 | `AssistantDock.ContextStrip`，长文本截断但 Host 侧保留完整必要上下文 | yootun 复合层 |

| 工作台内容形态 | 同一批业务对象可按空间墙、信息流、列表与工作区组织，卡片操作高频且紧凑 | 领域插件可自建 `WorkbenchCanvas` / `CardWall`，但必须提供键盘列表与完整状态 | 插件场景层 |
| 视觉节奏 | 悬浮顶栏、分区导航、卡片浮起、任务氛围和空态引导让工作台有空间层级，而不是一列表单 | 顶栏与操作件回到官方 primitives；卡片浮起、局部氛围、空态插画可由 yootun 复合层自建，强度低于内容 | yootun 复合层 + 插件场景层 |
| 任务化时间视图 | 排期、邮票和“下一条”把抽象日期变成可操作对象 | 日历/排期类插件可自建任务日历；日期单元必须可键盘聚焦并可打开详情 | 插件场景层 |
| 设置与模型选择 | 高频项直白，高级项折叠；默认模型可跟随宿主，也可显式选择 | 用官方 `SettingsForm`、`Menu`、`Modal` 重做；模型枚举与调用留在 Host | 官方底盘 + Host |

| 参考 | `dsh-context` 做得好的地方 | yootun 转化 | 归属层 |
|---|---|---|---|
| 洞察优先 | KPI、7 天用量、构成、热力图、排名、明细依次回答业务问题，而不是先丢原始表 | `KpiCard` + `DataCard` + `ChartFrame` 的标准洞察模板 | yootun 复合层 |
| 图表即筛选器 | 点击热力图、图例、工具或命令排名会反查会话明细，筛选 chip 可见可清除 | `FilterBar` + `ChartFrame` 联动协议；mark 可聚焦、可键盘选择 | yootun 复合层 |
| 图表语言 | 成对柱、donut、堆叠条、趋势带、热力图、treemap、timeline 各司其职 | yootun chart family；先选问题再选图，不按“看起来高级”堆图 | yootun 复合层 |
| Tooltip 与图例 | 悬停解释数值、类别和占比；图例可高亮/筛选，不只是一排色块 | `ChartTooltip` + `ChartLegend`，Escape/outside 行为遵循官方浮层规则 | yootun 复合层 |
| 加载形态 | 行骨架、图形骨架、donut 骨架与最终图形形状匹配 | `DataState`：loading / empty / error / partial 分别呈现 | yootun 复合层 |
| 视觉密度 | 紧凑卡片、细分割线、小尺寸图表控制和常驻筛选形成专业分析工作台 | yootun 洞察模板允许紧凑行高与小控件，但保持官方字号下限、hover 守卫和 640px 可读性 | yootun 复合层 |
| 数据色彩 | 类别色、趋势色和状态色帮助快速分区，图例承担解释与筛选 | 集中定义 `--yt-chart-*` / `--yt-data-*` 语义变量并映射官方 token；色彩不作为唯一信息 | yootun 复合层 |
| 密度控制 | 仪表盘信息密度高但仍保持分组、排序和路径清晰 | 插件可采用紧凑密度，但必须保持 640px 容器可读和键盘路径 | yootun 复合层 + 插件场景层 |

这两组的实现细节不作为规范：`dsh-media-desk` 的私有 `md-*` 原子件、杂志字体与氛围光斑，以及 `dsh-context` 的 Tailwind、`lc-*` 控件和分散状态色，都不能直接迁移。可迁移的是“任务现场、助手协作、数据回答、操作可恢复”的产品判断。

## 二、信息架构与页面模板

### 2.1 挂载位置

| 页面类型 | 官方插槽 | 规则 |
|---|---|---|
| 独立业务工作台 | root `sidebar.panellist` 注册入口，同 id 注册 root `main` keyed slot | 入口有 16px 图标、locale-aware 名称与稳定 order；一个业务域一个面板，不按内部 tab 拆多个侧栏入口 |
| 会话内分析页 | `conversation.view` | 仅当视图依赖当前 Session、投影或会话工具结果时使用；独立业务数据不放这里 |
| 设置 | 官方设置分区或 `SettingsForm` | 不在业务页面重复做全局配置；页面内偏好必须随业务数据持久化并可恢复 |
| 全局弹窗 | `shell.overlay` | 仅跨面板、需要宿主生命周期的确认或进度；普通表单优先内嵌或官方 Modal |
| 会话输入浮层 | `conversation.input.overlay` | 仅服务当前会话输入，不承载插件工作台主功能 |

页面组件必须通过 `ctx.effect()` 注册并在卸载时释放；插件重载后不依赖 localStorage 恢复 UI 选中态。

### 2.2 标准页面骨架

```text
PluginPage
├─ PageHeader
│  ├─ title + subtitle / status
│  ├─ primary action（最多 1 个）
│  ├─ settings / refresh / assistant toggle
│  └─ FilterBar（搜索、时间范围、分段筛选、排序）
├─ ContentRegion
│  ├─ KpiRow
│  ├─ TrendAndCompositionGrid
│  ├─ RankingAndDetailGrid
│  └─ Pagination / LoadMore
└─ AssistantDock（可选，默认有模型时可用）
```

- 顶层导航最多 5 个；超过时先拆信息架构，不允许两行 tab 挤压。
- 页面一级标题左侧对齐，操作右侧对齐；标题与内容的间距必须小于上一节与标题的间距。
- 筛选改变时重置分页；搜索输入、草稿和助手对话不在筛选变化时静默丢失。
- 主内容区保持 `min-width: 0` 与 `overflow: clip`；所有横向滚动只发生在表格或图表内部。
- 文本阅读页最大内容宽度 960px；仪表盘和工作台可使用可用宽度，但卡片网格必须有上限，不为拉宽而失去阅读单位。

### 2.3 响应式断点

以插件面板容器宽度计算，不使用浏览器窗口宽度：

| 宽度 | 布局 |
|---|---|
| ≥1120px | 主内容 + 360px 助手 Dock 并排；内容区仍至少 720px |
| 880–1119px | 助手为右侧浮层，宽度 `min(400px, 100%)`，带轻量遮罩；关闭后回到内容 |
| 640–879px | KPI 两列、图表单列；助手全宽底部或右侧面板 |
| <640px | 单列；筛选折行，操作按钮保持 44px 触达高度；表格提供卡片化或横向滚动方案 |

必须用 Container Query 或 `ResizeObserver` 处理面板宽度。助手浮层不能遮挡保存、取消、关闭等关键操作；Escape 关闭浮层时焦点回到触发按钮。

## 三、视觉与布局基线

本节只补充插件页面的密度与组织，不改变分册 05 的 token、圆角、材质和无障碍规则。

| 层级 | 规格 |
|---|---|
| 页面滚动区 | 桌面水平 padding 20px，窄容器 16px，移动 12px；纵向底部预留 32px |
| 页面分区 | 相邻一级分区纵向 20px；同一卡片内字段 8–12px；标题靠近自己的内容 |
| 页面头部 | 高度 48–56px；标题、状态、操作垂直居中；窄容器可折为两行 |
| 卡片 | R20、`--dsw-alias-bg-layer-1/2`、padding 14–18px；卡片标题 13px/500，操作放标题右侧 |
| KPI | 数值 20–24px，标签 12–13px；每行最多 6 个，附上时间范围或分母 |
| 图表卡 | 高度 180–320px；坐标轴与图例不超过两种字号，数值用 tabular numbers |
| 列表行 | 单行 36px 或紧凑 32px；两行主信息不超过 56px；长标题 ellipsis 并保留完整 title/详情 |
| 表格 | 表头 32px，行高 36–40px；首列左对齐，数字右对齐，操作列固定宽度 |
| 工具栏 | 控件高 28/36px，间距 4–8px；同类控件先成组，再与异类分开 |
| 浮层 | R28、`--dsw-alias-bg-layer-2`、`--dsw-elevation-prominent`；遮罩用官方 mask token |

所有间距必须解释归属关系；禁止把某一个插件的局部数值硬编码成全局新刻度。若官方 primitive 自带尺寸，以 primitive 为准，不用局部 CSS 覆写。

## 四、组件规范

### 4.1 按钮

必须复用官方 `Button`，禁止重写按钮原子。

| 场景 | 规格 |
|---|---|
| 页面唯一主操作 | `primary` + `md`，例如保存、生成、导入 |
| 次要操作 | `ghost` 或 `outline` + `md/sm` |
| 工具栏 / 图表切换 | `toolbar` + `sm`，可配 14–16px 图标 |
| 危险操作 | 使用官方风险确认模式；按钮语义用 error token，不用自定义红底 |
| 图标-only | 必须提供 `aria-label` 与 Tooltip；16px 图标放在稳定图标盒中 |
| 提交中 | disabled + `aria-busy` + 明确 busy 文案；阻止重复提交 |
| 无权限 / 前置缺失 | disabled 并用附近说明或 Tooltip 解释原因，不用悬空灰按钮 |

表单底部操作：主按钮在右，取消在其左；删除等危险按钮独立放在左侧，不以颜色相同的方式与主按钮并列。

### 4.2 输入框与表单

- 单行输入复用 `Input`；设置页优先 `SettingsForm` / `SettingsValueField` / `SettingsSecretField`。
- 字段结构为：label（13px）→ 控件 → hint（12px）→ error（`role="alert"`）。label、hint、error 必须进入 typed dictionary。
- 搜索框必须可清空；清空按钮有可访问名称，清空后焦点不丢失。
- 长文本使用 `InlineEditor` 或插件局部 textarea + CSS Modules；禁止为圆角、边框、焦点重写已有官方单行输入。
- 校验时机：格式在 blur 或提交时校验，业务唯一性在提交后呈现；失败时保留用户输入。
- 密钥、token、连接串只显示末尾或掩码；复制操作提供成功/失败反馈，不在日志或会话中回显明文。
- 数字输入必须声明单位、范围和步进；提交前把空值、NaN、越界转为明确错误。
- 日期范围、时间粒度和排序默认值要持久化；显式“自定义范围”优先于预设。

### 4.3 Tab、分段控制与导航

- 页面主导航用 `SegmentedTabs`：每个 tab 必须有 `id` / `panelId`、唯一 value 与 locale label；键盘 Left/Right/Home/End 行为保留。
- 视图形态切换（列表 / 卡片 / 图表、累计 / 增量）用 `SegmentedControl`，不超过 4 个选项。
- Tab 面板由调用方持有；切换不卸载时必须保留草稿，卸载时必须释放订阅与异步任务。
- 不允许双层等宽大 tab；第二层改为 `SegmentedControl`、菜单或页面内锚点。
- 当前页在顶部导航用 `aria-current="page"`；会话视图 tab 使用官方 slot 语义。

### 4.4 选择控件、菜单与开关

- 单选用官方 `Menu` / `MenuItemButton`，当前项显示 check 或明确状态；多选列表用 `Checkbox`。
- 布尔设置用 `Switch`；互斥的小组选项用 `SegmentedControl`，不用一排 Switch 模拟单选。
- 菜单必须处理 outside click、Escape、键盘焦点、视口翻转和祖先 clipping；不能溢出面板。
- 筛选 chip 显示已选值与数量，点击可清除；“全部” chip 与具体 chip 不重复计数。
- 原生 `<select>` 仅在官方表单约定或无法替换的宿主场景使用，并必须补齐 label 与焦点样式。

### 4.5 卡片、列表与表格

- 卡片标题结构：图标 + 标题 + 说明/时间范围 + 右侧控件；不要为装饰添加无语义图片。
- 重复卡片使用同一构图、padding、标题行和元信息行；不同状态用状态点或 Tag，不改变卡片基础材质。
- 列表主文本一行 ellipsis，次文本最多两行；元信息不挤压主文本。
- 表格列必须声明排序语义；排序按钮的 `aria-sort` 与视觉箭头一致。
- 行操作在窄容器收敛为 Menu；在宽容器最多露出两个高频按钮。
- 超过 100 行使用分页或虚拟列表；分页保留筛选与排序，并显示总数。
- 空列表提供下一步动作；失败列表保留已加载数据并提供 Retry，不整页替换成错误。

### 4.6 状态、标签与提示

- 状态用官方 `StateDot` / `Pill` / `Tag`，语义映射为 pending、running、success、warning、error、disabled、info。
- 状态颜色不能是唯一信息，必须伴随文本 label；同一状态跨页面颜色和词形一致。
- 悬停解释用 `Tooltip`， richer 信息用 `HoverCard`；不得用全局 `title` 代替所有可达提示。
- 短暂成功/失败用官方 Toast；数据破坏性操作的 Toast 可带 Undo，但 Toast 不承载唯一撤销入口。
- 表单和面板内错误用 in-place notice；错误文案短、可行动、中文不超过两句且不加句号。
- Empty / Loading / Error 三态必须与最终内容形状相似：列表用行骨架，图表用图形骨架，KPI 用数值骨架。

### 4.7 对话框与浮层

- 优先官方 `Modal`；宽度按 380 / 520 / 720 三档选择，不超过面板宽度。
- 打开后焦点进入第一个可交互字段或主按钮；Escape 关闭，关闭后焦点回到触发器。
- 表单对话框禁止提交即消失：失败保留草稿，成功后再关闭。
- 危险操作使用 `RiskConfirmation` 或同等显式确认；确认按钮说明动作对象，不使用裸“确定”。
- 浮层 z-index、portal、层叠和快捷键交由官方 primitive / slot 管理，插件不自挂 `<body>` 节点。
- 所有浮层动画必须有 reduced-motion 守卫。

## 五、数据图表规范

### 5.1 图表选择

| 问题 | 首选形态 | 规则 |
|---|---|---|
| 总量与关键指标 | KPI 卡 | 最多 6 个；每个值有标签、时间范围、分母或变化说明 |
| 时间对比 | 成对柱状图 / 折线图 | 少量离散日用柱状，连续趋势用线；双指标必须给出双轴或直接标注 |
| 构成占比 | Donut / 水平堆叠条 | 类别 ≤6，其余合并为 Other；中心显示总量 |
| 排名 | 水平条形列表 | 前 N + hidden 数；每行可筛选 |
| 分布与占比层级 | Treemap | 只适合规模对比，不适合精确值比较；必须支持 tooltip 和明细 |
| 活跃频率 | Heatmap | 最近 8 周 / 12 月；点击日期筛选 |
| 事件与依赖 | Timeline / lane 图 | 先时间轴，再泳道；箭头不表示无依据因果 |
| 进程与阶段 | Stage bar / pulse | 每阶段有开始、耗时、状态，失败可跳转日志 |

不确定时退回表格 + 一个摘要图；不得为了让页面看起来丰富而同时展示同一数据的多种等价图表。

### 5.2 图表卡结构

```text
ChartCard
├─ Header: icon + question-style title + range + controls
├─ Plot: axis / grid / marks / interaction layer
├─ Legend: color + label + value + delta + toggle/filter
└─ Footnote: data source, timezone, sampling, update time
```

- 标题写成业务问题（例如“最近七天用量如何变化”），不用图表类型作为标题。
- 坐标轴 0 / 25% / 50% / 75% / 最大值即可；数值格式稳定，不为每个 mark 重复单位。
- 空间不足时先省略次网格和次要 label，不缩小到不可读。
- 颜色来自官方语义或稳定的类别 token；同一数据维度跨页面同色。
- 类别颜色不能承载唯一含义，legend、tooltip 或直接 label 必须可读。
- 负值、缺失值、估算值必须显式标注；禁止把 undefined 画成 0。
- 图表必须有 `role="group"` 与 localized accessible name；可点击 mark 使用 button 语义并支持 Enter/Space。
- 若图表不可键盘访问，必须提供等价表格或详情列表，不能只用 `aria-hidden`。

### 5.3 交互与联动

- Hover/Focus tooltip 包含类别、数值、单位、时间、占比和必要的 note；tooltip 靠边时自动翻转，不允许遮挡当前 mark。
- 点击数据点后把它变成可见筛选 chip，并同步 KPI、排名与明细；再次点击或清除 chip 恢复。
- Legend 可高亮 / 隔离类别；筛选状态有明确数量和清除动作。
- 联动请求必须有 pending、失败和部分数据语义；不能在旧数据上无提示切换成新筛选。
- 多图表并发刷新时页面只保留一个整体 busy 语义；避免多个 spinner 相互闪烁。
- 长任务可显示进度、已处理数量或最后更新时间；无法量化时显示进行中状态，不虚构百分比。

## 六、插件助手 Dock

> 2026-11-26 起助手 Dock、操作回执与撤销暂缓：本节保留为目标设计，落排期前不作为评审项（1126 ui-accessibility 单 §A8）。

助手 Dock 是插件页面的任务级 AI 入口，目标是“在当前对象上问一句、改一步、看回执、可撤销”，不是复制主会话。

### 6.1 布局与解剖

```text
AssistantDock
├─ Header
│  ├─ title: Plugin Assistant / 插件助手
│  ├─ model chip: default or selected model
│  ├─ status: live / loading / unavailable
│  └─ actions: model picker, clear, close
├─ Context strip（当前对象或引用，可移除）
├─ Message stream
│  ├─ user message
│  ├─ assistant answer
│  ├─ operation receipts / errors / notice
│  └─ last undoable action
├─ Suggestions（空态 4 条；已有对话 2 条）
└─ Composer（上下文 chip + textarea + send/stop）
```

- 宽屏固定右侧 Dock，窄容器为浮层；每个插件页面最多一个助手实例。
- Dock 不遮住内容区的关键操作；打开时内容区压缩而不是不可交互。
- 助手默认宽度 360px，消息最大 88% 卡片宽度；长错误可展开，不挤破容器。
- 消息流自动滚动只在用户接近底部时执行；用户上翻后不强行拉回。
- 清空对话需要确认；仅清空助手消息，不删除业务数据。

### 6.2 模型与调用链

- 默认模型跟随企业激活后的默认模型（当前 `agentDefaultModel` 选择），不要求用户重复配 key。
- 插件可选“跟随默认”或指定 provider/model；模型列表由 Host 通过官方 LLM 服务枚举，前端不保存密钥。
- 模型调用必须在 Host 侧执行：使用官方 LLM call 接口、独立稳定的插件 sessionId、超时与 AbortSignal；禁止浏览器直接访问网关。
- 同一 Dock 同时只允许一个请求；发送后按钮变为 Stop，可中止并保留用户输入。
- 模型不可用时呈现明确降级：能做本地规则则说明“本地规则”，不能做则禁用发送并给出下一步，不伪造 AI 回答。
- 模型调用、输入摘要、输出计划、执行结果和失败原因要落入插件持久化审计/会话日志；不得把 `MODELS_API_KEY` 或请求头写入任何 UI、日志或模型消息。
- 助手调用不继承当前 DSH 主会话历史；只有用户明确引用的对象、选区或筛选作为上下文传入。

### 6.3 对话与操作语义

- 每条助手回答包含三部分之一或全部：自然语言回答、操作回执、错误/降级说明。
- 回执按对象逐条显示：做了什么、目标是什么、结果如何；可点击目标跳转。
- 修改类操作先计算计划，再原子提交；失败不写半状态，成功后才进入可撤销历史。
- 只有真正产生数据修改的回合显示 Undo；提问、查询和失败回合不占用撤销位。
- 撤销后业务数据与助手消息同步显示“已撤销”，不允许 UI 状态与数据状态分离。
- AI 输出 JSON 时在 Host 解析和校验；不能解析时降级为普通回答，不把原始大段输出直接倾倒在 Dock。
- 上下文 chip 显示当前对象、选区或筛选，可单独移除；引用原文过长时截断并在 Host 侧传完整必要上下文。
- 建议 prompt 来自插件任务域，不用“你可以做什么”这类空泛提示；首批建议可直接执行真实查询或修改。

### 6.4 Composer 细节

- textarea 初始 1 行，自动增高到最多 140px；继续输入进入内部滚动。
- Enter 发送，Shift+Enter 换行；中文/日文输入法组词期间 Enter 不发送。
- 发送按钮在空输入、请求中、模型不可用或未授权时 disabled，并保留可访问原因。
- 请求中可 Stop；停止后已生成的安全增量可保留为部分回答，未完成的操作计划不得执行。
- 草稿按插件 + 上下文对象保存；切换 tab 不丢失，页面卸载后按业务数据持久化策略处理。
- 助手浮层 Escape 关闭；若焦点在 composer 且有草稿，先只收起浮层，不删除草稿。

## 七、文案与国际化

- 每个插件维护 typed dictionary，`zh` 为 key-set source of truth，`en` 全量同步；后续如进入官方组合再补齐官方八语言。
- 字典键按语义命名，不用 `text1` / `labelA`；占位符显式声明。
- 图表标题、轴、图例、空态、错误、回执、撤销、助手建议全部进字典。
- 中文错误与提示最多两句，句末不加句号；按钮使用动词或动词短语。
- 数字、货币、百分比、日期、时长使用 locale formatter，不在字符串拼接里散落单位。
- 不迁移两个参考插件的业务文案、营销语气或品牌词；yootun 语气保持直接、具体、可执行。

## 八、实现与复用治理

### 8.1 组件分层与来源

| 需要的形态 | 来源与归属 | 判断 |
|---|---|---|
| Button、Input、Switch、Checkbox、Menu、Modal、Tooltip、Toast、Tabs、状态点 | 官方 `@deepseek-ai/dsh-client-ui-primitives` | 官方已有原子件，禁止重做 |
| 挂载、布局、设置分区、窗口安全距离 | 官方 slot / layout / settings 体系 | 插件不新建全局布局机制 |
| 品牌位、门禁、激活设置 | yootun 已有 brand/access 包 | 已有实现优先复用 |
| 工作台壳、助手 Dock、洞察卡、图表族、筛选条、状态族、回执 | `@yootun/dsh-client-ui-kit` | 官方没有的跨插件复合能力，首个插件批次建立 |
| 登录/采集/批量/作品查询等数据流 machine | `@yootun/dsh-client-workbench-machines`（共享核心）+ 插件 `flows.ts` 适配层 | 无 React/DOM 依赖的纯状态基座；竞态守卫随流进 machine，页面经 `useSyncExternalStore` 订阅；同构流第二个消费者出现时核心上移共享包，插件只留 Host action 与 schema 投影适配 |
| 领域画布、看板、日历、媒体墙、拓扑、专属空态 | 插件局部 CSS Modules / 组件 | 只服务单一业务域且不重做通用原子件 |

`@yootun/dsh-client-ui-kit` 不 speculative 预先创建；第一批插件落地时随真实消费者建立。首批预期组件：`PluginPageShell`、`PluginHeader`、`FilterBar`、`DataCard`、`KpiCard`、`ChartFrame`、`ChartLegend`、`ChartTooltip`、`DataState`、`AssistantDock`、`OperationReceipts`。同一形态第二个消费者出现时必须上移，不允许第三个插件复制。

### 8.2 自创组件准入流程

新复合组件或领域视觉必须记录以下决策，放在该插件批次文档的设计决策节：

1. 用户任务与交互问题：这个形态解决什么官方表单无法解决的问题；
2. 官方盘点：说明官方 primitive / slot 为什么不能直接承载；
3. 归属判断：yootun kit、插件局部，或暂局部但列出上移触发条件；
4. 组合边界：内部哪些控件必须使用官方原子件，哪些布局/图形可以自创；
5. 状态契约：loading、empty、error、partial、disabled、focus、hover、pressed、selected；
6. 主题契约：颜色、阴影、圆角、边框、动效全部映射官方 token 或集中语义变量；
7. 可达与适配：键盘路径、屏幕阅读器名称、640px / 880px / 1120px、reduced-motion；
8. 测试证据：组件逻辑、图表数据、明暗主题与关键交互验证。

“官方没有”是自创必要条件，不是免除规范的理由。自创复合件可以有自己的节奏和形态，但放进 DSH 后必须仍像官方产品的一部分。

### 8.3 技术红线

- 禁止 Tailwind、全局 CSS 注入、`!important` 布局补丁、插件级 reset、body/class 全局选择器。
- 禁止复制 `md-*` / `lc-*` 类名、SVG path、截图、插画、业务文案或数据结构。
- 禁止在 client 侧保存明文密钥或直接请求模型网关。
- 禁止 chart 库引入重量级运行时；优先 SVG/CSS 实现，确需库时先评估包体、主题 token、无障碍和离线构建。
- 禁止模型输出直接执行写操作；Host 必须校验目标、权限、操作 schema 与业务约束。
- 每个异步任务、订阅、定时器、observer 和 slot 注册都必须有释放路径。

### 8.4 测试与验收

每个插件至少交付：

- 组件逻辑 `node --test`：筛选、分页、状态机、回执、撤销、模型降级；
- Host 契约测试：同源路由鉴权、输入校验、模型调用失败、原子写入、权限拒绝；
- 图表数据测试：空集、零值、缺失值、极端值、类别合并、格式化；
- i18n 键集测试：zh/en 完整、占位符一致、无硬编码 copy；
- 明暗双主题目检；
- 640px / 880px / 1120px 三档容器目检；
- 键盘路径：tab、菜单、图表 mark、对话框、助手 composer；
- `prefers-reduced-motion` 目检；
- 助手三态：默认模型可用、模型失败降级、请求中停止（Dock 落地前不适用）；
- 写操作回执与撤销后数据一致性验证（Dock 落地前不适用）。

设计验收不通过时，功能验收不得标记通过。

## 九、插件设计评审清单

- [ ] 页面目标能用一句话说明；顶层导航 ≤5，内部层级不超过三层；
- [ ] 所有原子控件来自官方 primitive；官方没有的复合形态有明确 yootun kit 或插件场景层归属；
- [ ] 自创组件记录了官方盘点、状态契约、主题契约、键盘路径和上移触发条件；
- [ ] 输入、按钮、tab、菜单、卡片、列表、表格、浮层、状态提示符合第四节；
- [ ] 每个图表回答一个业务问题，支持 hover/focus、键盘或等价明细，并与筛选联动；
- [ ] KPI、图表、列表的加载/空/错误态形状匹配；
- [ ] 助手 Dock 的模型状态、上下文、回执、错误、撤销、停止和草稿行为完整（Dock 落地前不适用）；
- [ ] 模型调用全程在 Host，凭证不进入 client，写操作经过 schema 与权限校验；
- [ ] 明暗主题、窄容器、键盘、reduced-motion 实测通过；
- [ ] 文案全部 locale-owned，中文短提示句式合规；
- [ ] 没有复制社区插件的代码、素材、类名、业务文案或视觉体系。
